# DIMPIK 최종 화면 기준 UI 구현 명세

> **문서 목적:** 최종 승인된 `AI 도구 제거된 딤픽 화면` 목업을 실제 Windows 앱 UI로 구현하기 위한 **화면 중심 명세서**입니다. 기능 PRD가 아닌, 최종 목업의 배치·크기·표시·상호작용을 구현하는 기준입니다.  
> **기준 이미지:** `DIMPIK_최종_UI_기준_목업.png`  
> **제품:** DIMPIK(딤픽) · Windows 전용 · Microsoft Store + GitHub(MIT)  
> **기본 UI 방향:** 상단 1열 명령/편집 도구 + 그 아래 다중 캡쳐 탭 + 중앙 캔버스 + 하단 상태바. 우측/좌측 고정 패널, 별도 속성 행, AI 도구 없음.

![DIMPIK 최종 기준 목업](DIMPIK_최종_UI_기준_목업.png)

---

## 1. 절대 준수사항

1. **마지막 목업과 동일한 화면 구조**를 구현한다. 앱을 리디자인하거나 다른 리본 레이아웃으로 임의 변경하지 않는다.
2. **상단 한 줄에 주요 기능과 편집 도구가 배치된다.** `AI 도구` 및 AI 관련 메뉴/아이콘을 추가하지 않는다.
3. **탭은 상단 도구 모음 바로 아래**에 배치한다. 캡쳐가 완료되면 새 탭이 오른쪽에 추가되고 자동 활성화한다.
4. 도구별 속성은 **도구 버튼의 작은 ▼로 여는 앵커형 팝업**에서만 변경한다. 선택할 때마다 속성용 행을 추가하거나 고정 측면 패널을 열지 않는다.
5. 속성 팝업은 **오버레이**로 띄운다. 열린 동안에도 탭과 캔버스 위치/크기를 바꾸지 않는다.
6. **캔버스는 좌우 패널 없이 최대 너비**를 사용하고 캡쳐 이미지를 중앙에 표시한다.
7. 마지막 목업의 **연한 블루그레이 배경, 흰색 툴바, 파란 활성 상태, 절제된 테두리/그림자**를 유지하되 Windows 접근성 요구사항을 충족한다.
8. 기존 캡쳐·편집 기능은 재사용할 수 있어도, UI 변경 때문에 이미지 데이터나 미저장 편집을 잃지 않아야 한다.

## 2. 기준 화면 좌표 및 영역

기준 이미지 해상도는 약 **1408 × 1056 px**이다. 다음 수치는 **목업 픽셀을 바탕으로 한 시각적 기준**이며 실제 WinUI 3 구현에서는 **DIP** 기준으로 DPI/폰트 배율에 맞춰 조정한다. 픽셀 고정 절대배치 금지.

| 구역 | 목업 기준 대략적 Y | 화면 구성 | 구현 원칙 |
|---|---:|---|---|
| A. 타이틀바 | 0–43 | 좌측 앱 아이콘 + `딤픽 DIMPIK v1.0.0`, 우측 최소화/최대화/닫기 | 높이 약 40–44 DIP |
| B. 메인 도구 모음 | 44–145 | 새 캡쳐부터 도움말까지 **단일 가로 행** | 높이 약 96–104 DIP, 도구 가운데 정렬 |
| C. 캡쳐 탭 | 145–203 | 썸네일·제목·닫기·`+` | 높이 약 54–60 DIP |
| D. 캔버스 작업 영역 | 204–989 | 이미지 중앙 배치, 주변 여백 | 남은 영역 전부 차지, 스크롤/줌 |
| E. 상태바 | 990–1056 | 좌측 이미지 정보, 우측 줌 | 높이 약 52–64 DIP |
| F. 도형 설정 팝업 | 도구 아래 오버레이 | 도형/색상/선 두께/채우기 | 폭 약 320–350 DIP; 탭·캔버스 위로 떠 있음 |

> 타이틀바 포함 전체 높이가 작아지면 위 수치를 고정하지 말고, 상단 도구 밀도를 축약하고 캔버스 최소 표시 영역을 보장한다.

## 3. A — 타이틀바

- **왼쪽:** 작은 정사각 DIMPIK 앱 아이콘, `딤픽 DIMPIK v1.0.0`.
- **오른쪽:** Windows 표준 최소화/최대화/닫기.
- 배경은 매우 연한 블루그레이, 제목은 진한 회흑색.
- 앱 버전은 실행 버전에서 바인딩하고 하드코딩하지 않는다.
- 사용자 임의 영역이 창 드래그를 막지 않도록 제목 영역을 드래그 가능하게 유지한다.
- 앱 아이콘은 승인된 DIMPIK 로고 자산을 사용한다. 목업에 그려진 단순 아이콘을 원본으로 간주하지 않는다.

## 4. B — 상단 한 줄 도구 모음

### 4.1 목업에 표시되는 정확한 순서

| 그룹 | 왼쪽부터 표시 | 기본 상태/동작 |
|---|---|---|
| 캡쳐 | `새 캡쳐 ▼` | 기본 강조 버튼. 본체=기본 캡쳐 시작, ▼=캡쳐 방식 선택 |
| 파일 | `열기`, `저장`, `복사` | 실행/저장/현재 이미지 복사 |
| 편집 이력 | `이전`, `다시` | Undo/Redo, 비활성 상태는 연한 회색 |
| 주석 | `도형 ▼`, `펜 ▼`, `형광펜 ▼`, `텍스트`, `번호` | 도형 버튼이 선택된 상태를 기준으로 표시 |
| 효과 | `모자이크`, `블러` | 대상 영역/객체에 적용 |
| 이미지 편집 | `자르기`, `크기 조절`, `영역 복사` | 현재 이미지/선택 영역 기준 |
| 기타 | `더보기 ⋯` | 상대적으로 낮은 빈도 명령 |
| 관리 | `캡쳐 기록`, `설정`, `도움말` | 오른쪽 정렬, 팝업 또는 별도 화면 |

**중요:** 위 그룹의 작은 구분선/간격은 목업처럼 유지한다. 모든 기능을 큰 카드를 둘러싼 리본 그룹으로 다시 구성하지 않는다.

### 4.2 버튼 시각 규칙

- 버튼은 **아이콘 위, 한글 라벨 아래**의 세로형 아이콘 버튼이다.
- 툴바 높이는 약 96–104 DIP, 아이콘 약 20–24 DIP, 라벨 약 12–13 DIP.
- `새 캡쳐`는 파란 강조색이 아닌 경우에도 우선순위를 확실히 구분한다. 목업의 `새 캡쳐`는 **아이콘·글자 파란색 / 흰 배경** 톤을 기준으로 한다.
- 도구 버튼 선택 시 둥근 **연한 파란 배경**으로 표시한다. 예시: `도형` 선택.
- 본체 클릭은 **도구 선택/실행**, ▼ 클릭은 **속성 팝업**을 연다.
- 비활성 버튼은 대비가 낮은 회색, 마우스 오버는 은은한 배경, 포커스는 키보드에서 식별 가능한 윤곽선.
- 아이콘은 일관된 선 두께의 자체/라이선스가 확인된 세트로 구현하고, 목업에 포함된 타사 로고/아이콘을 그대로 복사하지 않는다.

### 4.3 도구 모음 위치 옵션

- **기본: 상단**, 즉 이 문서의 마지막 목업과 동일한 배치.
- **설정에서 좌측 배치 선택 가능**하되, 이는 별도 화면 변형이며 상단 기본 화면에 좌측 패널을 함께 표시하지 않는다.
- 좌측 배치 시 캡쳐/파일/관리 명령은 상단에 유지하고, **주석·효과·이미지 편집 도구만** 좌측으로 이동한다.
- 상단/좌측 중 선택한 배치를 앱 재시작 후에도 유지한다. 도구별 속성 팝업은 선택 위치를 기준으로 나타난다.

## 5. C — 탭 영역

### 시각 구성

- 마지막 목업처럼 툴바 아래에 작은 카드형 탭을 왼쪽부터 배치한다.
- 각 탭: **작은 이미지 썸네일 + 제목 + (필요 시 `*`) + 닫기 `×`**.
- 기본 예시: `캡쳐 1 *`, `캡쳐 2`, `문서화면.png`, `+`.
- **활성 탭:** 밝은 배경, 하단 파란 선. 비활성 탭은 연한 회색 톤.
- 탭 높이는 약 44–50 DIP, 썸네일은 약 24–28 DIP.
- `+`는 사용자 요구에 따라 **새 캡쳐 시작** 버튼으로 사용한다. 탭 헤더의 `+`도 툴바의 `새 캡쳐`와 동일한 기본 캡쳐 동작을 호출한다.

### 필수 동작

1. 캡쳐 성공 시 `CaptureDocument`를 추가하고 **새 탭 활성화**. 기존 탭은 보존.
2. 이미지 파일 `열기` 시 별도 탭 생성.
3. 탭 전환 시 해당 탭의 이미지·줌·스크롤·선택 객체·Undo/Redo 이력이 복구된다.
4. 내용이 수정됐고 저장되지 않았다면 제목 뒤 `*`를 표시한다.
5. 미저장 탭을 닫으면 `저장 / 저장하지 않음 / 취소`를 묻는다. 일괄 종료에서도 데이터 손실 방지.
6. 탭이 많을 때 가로 스크롤 또는 목록 메뉴를 제공한다. 기존 탭을 너비 0으로 압축하지 않는다.
7. 탭 제목/썸네일은 접근성 이름을 제공하고 키보드 탐색이 가능해야 한다.

## 6. D — 캔버스 영역

- 목업과 같은 **연한 블루그레이 워크스페이스**를 사용한다.
- 캡쳐 이미지는 **중앙 정렬**, 필요한 경우 얇은 그림자로 배경과 구분한다.
- 이미지 위에는 기존 주석(사각형, 화살표, 번호, 모자이크 등)을 **편집 가능한 객체**로 렌더링한다.
- 원본 이미지 픽셀은 별도로 보존하고 주석을 이미지에 즉시 합성하지 않는다. 저장/내보내기 시 렌더 결과를 생성한다.
- 스크롤/줌 시 주석의 위치가 원본 이미지 좌표와 일치해야 한다.
- 이미지가 창보다 클 때 스크롤을 허용하고, 이미지 맞춤/100%/확대·축소 기능을 제공한다.
- **좌·우 고정 도구 패널과 속성 패널을 배치하지 않는다.** 기본적으로 이미지 공간이 전체 가로 폭을 차지한다.
- 선택 객체의 핸들, 범위, 커서는 필요할 때만 나타난다. AI 안내 팝업은 없다.

## 7. F — 도형 속성 팝업 (최종 목업에서 열려 있는 상태)

### 표시 위치와 계층

- 상단 `도형 ▼` 바로 아래에 앵커로 열린다.
- 팝업 너비 약 320–350 DIP, 내부 패딩 약 16–20 DIP, 모서리 12–16 DIP, 얕은 그림자.
- 탭 영역과 캔버스 위를 덮을 수 있다. **독립 행을 만들지 않는다.**
- 창의 오른쪽/아래쪽 경계와 충돌 시 가로 이동하거나 위쪽으로 뒤집어 띄운다.
- **화면 바깥 클릭, Esc, 다른 도구 선택 시 닫는다.** 팝업이 닫혀도 선택 도구/설정은 남는다.

### 팝업 내부 콘텐츠 (목업 순서)

| 순서 | 섹션 | UI | 의미 |
|---|---|---|---|
| 1 | `도형 종류` | 사각형, 원, 둥근 사각형, 직선, 화살표, 삼각형 아이콘 | 한 개만 선택, 선택 아이콘은 연한 파란 배경 |
| 2 | `선 색상` | 검정·빨강·주황·노랑·초록·파랑·보라 원형 스와치 + 사용자 색상 | 현재 선택 스와치에 링 표시 |
| 3 | `선 두께` | `3 px ▼` | 1/2/3/5/8/10 px 등 선택, 숫자 입력은 확장 가능 |
| 4 | `채우기` | `도형 내부 채우기` 체크박스 + 채우기 색상 | 체크 전엔 채우기 비활성. 색상 선택 별도 팝업 |

- 목업의 기본 선택은 **사각형 + 빨간 선 + 3px + 내부 채우기 미선택**이다.
- 도형별 설정은 마지막 사용값을 기억하고 새 객체에 적용한다.
- 이미 그린 도형을 선택 후 같은 팝업에서 속성을 바꾸면 해당 객체만 수정한다.
- 색상 직접 지정은 별도 간결한 2차 팝업(HEX/RGB 및 색상판)으로 제공한다.
- 2차 팝업은 첫 번째 팝업의 배치를 무너뜨리지 않도록 **연결형 Flyout**으로 연다.

### 도형 버튼 동작

```text
도형 본체 클릭 → 현재 도형 도구 즉시 활성화 → 캔버스에서 드래그해 그리기
도형 ▼ 클릭   → 도형 속성 팝업 열기/닫기
팝업에서 옵션 변경 → 다음에 생성하는 도형 또는 선택된 기존 도형에 반영
```

> 펜/형광펜에도 동일한 팝업 패턴을 적용한다. 텍스트/번호는 필요한 경우 객체 선택/더보기에서 글꼴·크기·번호 스타일을 제공하되 별도 설정 행을 추가하지 않는다.

## 8. E — 상태바

- **왼쪽:** 이미지 아이콘, 원본 이미지 크기 `937 × 606 px`, 이미지 형식 `PNG`.
- **오른쪽:** 화면 맞춤 아이콘, `−`, `100% ▼`, `+`, 전체 화면/캔버스 최대화 아이콘.
- 새 캡쳐/탭 전환 후 현재 탭의 메타데이터와 줌 배율로 갱신한다.
- 줌 배율은 25%, 50%, 75%, 100%, 125%, 150%, 200%, 맞춤 등 제공할 수 있다. 휠+Ctrl 지원 권장.
- 이미지 크기 표시는 **원본 픽셀 수**이며 UI에 표시된 렌더링 크기가 아니다.
- 상태바의 확대/축소는 캔버스 렌더링에만 영향을 주며 원본 이미지를 리샘플링하지 않는다.

## 9. 반응형 규칙

폭 변화에 따라 **도구 표시가 축약·확장되는 동작**만 지원한다. 디자인과 그룹 배치는 DIMPIK만의 것이다.

| 사용 가능한 툴바 너비 (DIP, 초기 가이드) | 표시 규칙 |
|---|---|
| ≥ 1300 | 모든 버튼 아이콘+텍스트 표시. 마지막 목업의 확장형 |
| 1000–1299 | 상대적으로 덜 쓰는 기능은 `더보기`로 이동, 아이콘 간격 축소 |
| 720–999 | 핵심 도구 중심, 일부 라벨 감추기, 작은 아이콘 버튼으로 전환 |
| < 720 | 새 캡쳐·열기·저장·선택 도구·더보기 중심의 압축 구성. 기능은 메뉴에서 접근 가능 |

- 실제 기준은 **그룹별 최소 너비를 측정**해 결정한다. 위 숫자는 초기 시제품 가이드이며 테스트 후 보정한다.
- 가장 중요한 `새 캡쳐`와 탭 영역은 접근 가능하게 유지한다.
- 축약 시 버튼의 그룹과 순서는 의미상 유지하며 기능을 제거하지 않는다.
- 창 크기 변경 중 선택 객체, 열린 탭, 편집 내용이 초기화되지 않는다.
- 열린 Flyout은 기준 버튼이 이동/숨김 상태가 되면 안전하게 닫거나 새 위치로 재배치한다.
- DPI 100/125/150/200%, Windows 텍스트 배율 및 키보드 포커스에서도 클릭 영역을 확보한다.

## 10. 색상/타이포/간격 기준

아래 색상은 이미지에서 시각적으로 추출한 **근사 디자인 토큰**으로, 정확한 브랜드 원본 색상값을 뜻하지 않는다. 실제 구현 전 앱 테마에서 미세 조정 가능.

| 토큰 | 초기 값(예시) | 용도 |
|---|---|---|
| `AccentBlue` | `#2563EB` | 활성 버튼/탭 하단선/포커스 |
| `ToolbarBackground` | `#FCFDFE` | 상단 도구 모음 |
| `WindowBackground` | `#F4F7FC` | 전체 배경 |
| `CanvasBackground` | `#EAF0FA` | 중앙 워크스페이스 |
| `SelectedToolBackground` | `#E2EBFF` | 선택 도구 배경 |
| `TextPrimary` | `#111827` | 기본 텍스트 |
| `TextSecondary` | `#667085` | 보조 정보 |
| `BorderSubtle` | `#DFE6F0` | 얇은 구분선 |
| `PopupBackground` | `#FFFFFF` | 속성 Flyout |
| `Danger/AnnotationRed` | `#EF4444` | 편집용 기본 빨강(브랜드 강조색과 별개) |

- 기본 글꼴: Windows의 한글/영문 읽기 좋은 시스템 UI 폰트(예: Segoe UI + 적합한 한국어 폴백).
- 라벨 12–13 DIP, 일반 텍스트 13–14 DIP, 타이틀 15–17 DIP 기준.
- 모서리 반경 6–12 DIP, 팝업은 12–16 DIP.
- 도구 버튼 터치/마우스 히트 영역은 가급적 최소 32×32 DIP 이상 보장.
- Light 모드가 기준 이미지이며 Dark/고대비 모드는 후속 테마 지원 시 의미별 토큰을 사용한다.

## 11. WinUI 3 구현 매핑

| UI 요소 | 권장 구현 |
|---|---|
| 커스텀 타이틀바 | `AppWindow` / `ExtendsContentIntoTitleBar`, 드래그 영역 지정 |
| 상단 명령/도구 | `Grid` + `ItemsRepeater` 또는 자체 `AdaptiveToolbar` 컨트롤 |
| ▼ 분리 도구 버튼 | `SplitButton` 또는 별도 Primary/Secondary 버튼을 묶은 커스텀 컨트롤 |
| 도구 속성 | `Flyout` / `MenuFlyout` + `FlyoutBase.ShowAt(...)` |
| 캡쳐 탭 | `TabView` 또는 커스텀 탭 헤더. 문서 모델과 분리 |
| 캔버스 | 커스텀 렌더링 뷰 + 이미지 레이어/주석 레이어 + 줌 변환 |
| 하단 상태바 | `Grid` + `StackPanel`, 우측 줌 제어 |
| 도구 상태 | MVVM `ActiveTool`, `ToolSettings`, `SelectedAnnotation` |
| 설정 유지 | 사용자별 로컬 설정 저장(도구 위치/최근 값) |

### 컴포넌트 구조 예시

```text
DimpikShell
 ├─ TitleBar
 ├─ AdaptiveToolbar
 │   ├─ CaptureCommands
 │   ├─ FileCommands
 │   ├─ EditHistoryCommands
 │   ├─ AnnotationTools
 │   │   └─ ShapeToolFlyout / PenToolFlyout / HighlighterFlyout
 │   ├─ EffectsAndImageTools
 │   └─ UtilityCommands
 ├─ CaptureTabStrip
 ├─ CaptureWorkspace
 │   └─ ActiveDocumentCanvas
 └─ ImageStatusBar
```

**레이아웃 원칙:** 상단과 하단은 `Auto`, 캔버스만 `*` 공간을 쓴다. 도구 팝업은 Overlay/Flyout으로 배치하며 레이아웃 행(Row)으로 삽입하지 않는다.

## 12. 화면 상태 정의

| 상태 | 화면 표현 |
|---|---|
| 이미지 없는 최초 실행 | 탭 없음; 중앙에 작은 `새 캡쳐` 안내와 시작 버튼(목업과 동일한 스타일 적용) |
| 여러 캡쳐 열림 | 탭 여러 개, 현재 탭만 활성 |
| 도형 선택 | `도형` 버튼 연한 파랑 강조 |
| 도형 속성 열림 | 해당 버튼 아래 앵커 팝업, 이미지/탭 위치 고정 |
| 편집 객체 선택 | 캔버스에서 객체 핸들 표시, 속성 팝업은 사용자가 열었을 때만 표시 |
| Undo 불가 | `이전` 비활성 회색 |
| 편집 후 미저장 | 탭 제목에 `*` |
| 기록 팝업 열림 | 별도 팝업/플라이아웃, 고정 우측 패널 추가 금지 |
| 캡쳐 중 | 앱 창을 캡쳐 대상에서 적절히 제외/숨기고, 종료 후 기존 탭 상태 유지 |

## 13. 키보드/포커스/접근성

- `Ctrl+O` 열기, `Ctrl+S` 저장, `Ctrl+Z` 실행 취소, `Ctrl+Y` 다시 실행, `Ctrl+Tab` 다음 탭, `Ctrl+W` 탭 닫기, `Esc` 팝업 닫기/현재 도구 작업 취소를 기본으로 검토한다.
- 새 캡쳐 단축키는 시스템 기본 키와 충돌할 수 있으므로 설정에서 변경 가능하게 한다.
- 아이콘 버튼에 한글 접근성 이름·툴팁·키보드 포커스를 제공한다.
- 색상 선택은 색상만으로 구분하지 않고 선택 윤곽선 및 이름을 표시한다.
- 스크린 리더에서 탭 제목/미저장 상태/선택 도구를 알 수 있어야 한다.

## 15. 검수 체크리스트 (UI 승인 기준)

- [ ] 타이틀 → 상단 도구 한 줄 → 탭 → 캔버스 → 상태바 순서가 정확하다.
- [ ] **AI 도구 아이콘·버튼·메뉴가 존재하지 않는다.**
- [ ] 기존 캡처·이미지 편집 앱 UI를 그대로 복제하지 않고 최종 DIMPIK 목업의 스타일을 구현했다.
- [ ] 상단에 별도의 속성 행이 없다.
- [ ] 좌측/우측 고정 속성 패널이 없다.
- [ ] 도형 ▼를 누르면 목업과 비슷한 크기의 팝업이 해당 버튼 아래 열린다.
- [ ] 팝업을 열고 닫아도 탭이나 캔버스가 밀리지 않는다.
- [ ] 도형 종류, 선 색상, 선 두께, 채우기 옵션이 동작하고 값이 반영된다.
- [ ] 캡쳐할 때마다 새 탭이 생성되고 기존 편집 결과가 보존된다.
- [ ] 탭 활성 강조·썸네일·미저장 `*`·닫기 버튼이 표시된다.
- [ ] 캔버스 좌우 전체 영역을 활용하고, 확대/축소·화면 맞춤이 동작한다.
- [ ] 100%, 125%, 150%, 200% DPI에서 요소가 잘리거나 겹치지 않는다.
- [ ] 가로 폭을 축소하면 툴바가 단계적으로 축약되고 기능이 더보기에서 접근 가능하다.
- [ ] 1개 이상의 미저장 캡쳐가 있는 상태에서 종료/탭 닫기 시 데이터 손실이 없다.
- [ ] 키보드 조작, 툴팁, 포커스 표시가 정상 작동한다.

## 16. 개발 적용 시 지시문

> **이 문서를 UI 구현의 단일 기준으로 사용한다.** `DIMPIK_최종_UI_기준_목업.png`가 시각적 원본이며, 임의로 상단 도구를 여러 줄로 나누거나 좌우 속성 패널을 추가하지 않는다. 캡쳐/편집 기능과 저장 로직은 유지하되, UI 계층과 상호작용을 이 문서에 맞게 교체한다. 이미지 캔버스의 실제 Azure 화면은 레이아웃 확인을 위한 예시이며 앱에 내장할 UI 자산이 아니다. AI 관련 버튼·메뉴는 이번 UI 범위에서 완전히 제외한다.

**별도 산출물 권장:** ① 최종 화면 XAML·ViewModel, ② 재사용 `AdaptiveToolbar`/`ToolFlyout` 컴포넌트, ③ 화면 폭·DPI별 스크린샷 테스트, ④ 변경 전/후 기능 회귀 테스트.
